# Задание 5. Запуск стека через Compose

**Что делаем:** поднимаем оба контейнера одной командой и проверяем
приложение в браузере.

## Шаг 1. Запустите стек

Из папки задания 4:

```bash
cd ../task04-compose-files
docker compose up -d --build
```

Разбор:
- `up -d` — поднять все сервисы в фоне;
- `--build` — сначала собрать образ web из Dockerfile.

Первая сборка займёт пару минут (ставятся зависимости).

## Шаг 2. Проверьте, что оба сервиса живы

```bash
docker compose ps
```

## Шаг 3. Проверьте приложение

```bash
curl http://localhost:5001
```

Должен прийти HTML со списком: Alice, Bob, Charlie.
Откройте http://localhost:5001 в браузере — то же самое красиво.

Если сразу после запуска пришла ошибка 500 — не паникуйте: web стартует
быстрее, чем PostgreSQL успевает подняться, и первая пара запросов падает.
Подождите 10 секунд и повторите. Как устранить эту гонку по-настоящему
(healthcheck + depends_on с условием) — разбираем в pro03.

> В вебинаре приложение проверяли на порту 5000, хотя слушает оно 5001 —
> мы исправили несовпадение: порт один и тот же в `app.py`,
> `EXPOSE`, `ports` и в браузере.

## Шаг 4. Посмотрите логи

```bash
docker compose logs web | tail -5
docker compose logs db | tail -5
```

## Шаг 5. Остановите стек

```bash
docker compose down
```

Вопрос письменно: что будет с таблицей `users`, если выполнить
`docker compose down -v` (с флагом `-v`)? Подсказка: вспомните задание 7
первой лабораторной.
