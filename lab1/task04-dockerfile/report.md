## Задание 4. Первый Dockerfile

### Ход работы

1. Создал приложение app.py:

    ```python
    print("Hello, Docker!")
    ```

2. Заполнил заготовку Dockerfile. Итоговое содержимое:

    ```dockerfile
    FROM python:3.8-slim

    WORKDIR /app

    COPY app.py .

    CMD ["python", "app.py"]
    ```

    В качестве базового образа выбран python:3.8-slim — облегчённый
    вариант Python 3.8 (суффикс -slim). Команда запуска записана в
    списочной форме (exec-форма): ["python", "app.py"].

### Пояснение к каждой инструкции

**FROM** — задаёт базовый образ, с которого начинается сборка: все
следующие инструкции наслаиваются поверх него. Мы берём python:3.8-slim —
внутри уже есть интерпретатор Python 3.8, а slim-вариант не содержит
компиляторов и лишних пакетов, поэтому образ получается компактным
(около 130 МБ против примерно 1 ГБ у полной версии).

**WORKDIR** — устанавливает рабочую директорию внутри образа (/app).
Все последующие инструкции COPY и команда CMD выполняются относительно
этого пути. Если директории нет, Docker создаст её сам.

**COPY** — копирует файлы из контекста сборки (нашей папки task04-dockerfile)
внутрь образа. Строка COPY app.py . кладёт app.py в текущую рабочую
директорию образа, то есть в /app.

**CMD** — задаёт команду по умолчанию, которая выполняется при запуске
контейнера: docker run по этому образу запустит python app.py.
Формат-список (exec-форма) означает, что процесс запускается напрямую,
без промежуточной оболочки sh — так работают сигналы (например, Ctrl+C
и docker stop корректно доходит до приложения).

### Вывод

Dockerfile — это «рецепт» сборки образа: FROM определяет основу,
WORKDIR готовит рабочее окружение, COPY добавляет в образ файлы
приложения, CMD указывает, что запускать при старте контейнера.
Сам образ будем собирать в следующем задании (docker build).
