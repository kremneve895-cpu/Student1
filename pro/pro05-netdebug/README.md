# Pro 5. Диагностика сети контейнеров

**Цель:** научиться расследовать сетевые проблемы в Docker, а не
перезапускать всё наугад.

## Сценарий (поломайте себе сами)

Поднимите стек из lab2/task05, затем «сломайте» его: отсоедините
сервис `db` от сети (`docker network disconnect`). Приложение перестанет
работать.

## Задача

Расследуйте поломку инструментами, документируя каждый шаг:

1. `docker compose ps` / `docker ps` — контейнеры-то живы?
2. `docker network inspect` — кто вообще в этой сети?
3. Из контейнера `web`: `docker exec` + `ping db` / `getent hosts db` —
   имя разрешается?
4. `docker compose logs db` — база здорова сама по себе?
5. Почините, не пересоздавая стек (подсказка: есть команда, обратная
   disconnect).

## Критерий приёмки

Отчёт-расследование: симптом → команда → вывод → вывод из вывода,
на каждом шаге. В конце — одна фраза, в чём была причина.
