# Pro 6. Лимиты ресурсов

**Цель:** ограничить контейнер по CPU и памяти и наблюдать, что происходит
при превышении.

## Задача

1. Запустите контейнер с лимитом памяти 128 МБ и половиной CPU.
2. Внутри нагрузите его (например, python-скрипт, который съедает память
   списком, или `stress`, если поставите).
3. Наблюдайте через `docker stats` и `docker inspect`:
   - что происходит при превышении памяти (найдите в inspect поле
     `OOMKilled`);
   - как выглядит throttling по CPU (`docker stats` — колонка CPU%).
4. Повторите то же через compose: ключи `mem_limit`/`cpus` или
   секция `deploy.resources` (разберитесь, что поддерживает ваша версия
   compose).

## Критерий приёмки

Скриншот `docker stats` под нагрузкой + `docker inspect` с `OOMKilled: true`
+ письменный ответ: почему в проде контейнеры без лимитов опасны
(что может сделать один «прожорливый» сервис с соседями на хосте)?
